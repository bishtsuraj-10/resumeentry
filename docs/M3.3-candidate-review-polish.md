# M3.3 candidate review polish

The review workspace now uses a compact identity/action header, readable field values, quieter verification indicators and six scroll-synchronized navigation groups. The application keeps its existing theme preference; the verification browser explicitly selects light mode for screenshots only.

## Workflow and layout

- Overview includes contacts and summary/preferences. Experience and Education have separate destinations. Skills & Projects keeps those adjacent. Credentials & More includes certifications, links and additional qualifications. Evidence opens provenance. All existing sections remain mounted, preserving drafts when navigating.
- Desktop uses the workspace height with only candidate information and PDF panels scrolling. The width slider remains keyboard operable. Mobile stacks bounded information and document regions with an outer workspace scroll and the original-document action in the sticky header.
- Values appear first. Machine extraction uses a subtle dot with an accessible label, verified fields use a green check and Verified, and uncertain fields use Check source. Missing optional values are muted information. The legend explains the states once; confidence describes extraction reliability only.
- Expand Edit identity/profile/record, select a supported field, then edit or explicitly verify it. Save that field or batch pending corrections in the header. Review completion waits for drafts. Exact field evidence, revision-safe PATCH requests, conflict recovery, validation errors and unsaved-navigation warnings retain the M3.1/M3.2 behavior. Record timestamps continue to mean partially reviewed, not verification of every field.
- PDF preview defaults to Fit width and responds to panel resizing. Percentage zoom, page controls and open in new tab remain available. Canvas dimensions preserve page aspect ratio. The authenticated file endpoint, permissions, failure recovery and original accessible PDF link are unchanged.

## Data mappings and limits

The [M3.2 persisted mapping table](M3.2-candidate-review-workspace.md#persisted-data-mappings) remains authoritative. Header/basic contacts come from ResumeExtraction, profile/preferences from CandidateProfile, and each structured section from its corresponding persisted M2 relation. Projects use ProjectSkill technologies, skills use ResumeSkill and Skill/SkillTerm, and languages intentionally use typed CandidateAdditional records. Provenance and exact verification use ExtractionRun and CandidateEvidence through the existing authorized APIs. No displayed section is populated from newly parsed text.

Existing limits remain: skill-context edits do not provide an exact context verification path, manual-field snapshots are bounded and older verification may require paginated provenance, and legacy timestamps do not prove exact field verification. These limits are displayed/documented rather than filled with invented data. There is no new missing section mapping.
