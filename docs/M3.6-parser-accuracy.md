## Root causes and implementation

- **Column ordering:** a right-column Summary heading appeared above the first horizontally paired row. The reader put it in the shared header, then encountered left-column Contact before reaching the Summary body. `pdf-layout.ts` now starts the column body at the earliest recognized section heading. The heading stays with its column. Summaries in resume-04, resume-10, resume-13 and resume-18 now match their sources; successful tables, scans and other layouts remain covered by the original-PDF gates.
- **Profile URLs:** the old extractor required an intact HTTP scheme for generic domains and also searched project sections. It missed the OCR-damaged scheme in resume-06 and mixed project ownership into CandidateLink. It now recognizes fully stated bare destinations in profile/header context, repairs only scheme punctuation, rejects email-domain fragments and unrelated labelled destinations, validates safe URLs and deduplicates them. Project and certification sections retain their own URLs.
- **PDF annotations:** URI destinations were absent from extracted text. The layout reader now attaches a validated destination to its visible label at the original coordinates before section extraction, so ownership remains contextual. Unsafe URLs and annotations without a text anchor are ignored. A real generated PDF verifies annotation-only LinkedIn/portfolio links, visible/hidden deduplication, employer/reference exclusion and project/certification ownership through `LocalResumeParser`.
- **Location wrapping:** resume-10's `District of` / `Columbia, United States` continuation was not recognized. Normalization joins known place-name continuations, and identity extraction joins adjacent, explicitly labelled address lines using region, country and postal-code evidence. Tests cover the affected original PDF, wrapped countries, Indian regions, multiline labels and postal addresses. Only `locationText` is populated; company/university/project locations are excluded.
- **Employment tables:** recognized column labels could be mistaken for the preceding employment header, hiding the actual row's employer/role. Those label rows are excluded before block assembly. A focused cell-separated tuple regression protects this case alongside all original table-heavy PDFs.
- **Designation preservation:** existing role ranking remains in place, including current versus previous employment and independent headline extraction. A small standalone-role vocabulary extension preserves `Intern`/`Trainee` suffixes. Summary mentions of colleagues or desired roles later in a sentence are excluded as designation evidence; leading self-descriptions remain supported. Tests protect seniority, specialties, uncommon titles, multiple roles and ambiguous prose.

`section-detector.ts`, confidence calculations and review thresholds needed no changes. The layout reader supplies the corrected heading/body order to the existing document-reader pipeline. Existing worker/persistence architecture remains in use.

## Separate URL targets

The historical flattened `expectedFields["links.url"]` contains both 40 independent profile URLs and 40 project URLs. Using all 80 as a CandidateLink target would reward incorrect duplication. The evaluator projects the untouched structured `expected.links`, `expected.projects` and `expected.certifications` into separate targets. Both the dedicated evaluator and the existing synthetic-batch evaluator use this projection and normalize protocol-less expected URLs.

This corpus has no certification URL targets. Its 0/0 result is absence, not a measured certification-link recall claim; the annotation fixture supplies positive coverage. A project URL is also allowed in CandidateLink when the source independently presents that destination as a candidate portfolio, which has its own regression.

## Remaining limitations

The target mandatory fields and employment gates all succeed, but optional structured extraction still has misses and extras. The exact-value report records skills at 221 hits/49 extras/19 misses, project skills at 91/3/1, education field of study at 24/0/1, certification names at 37/7/3, issuers at 35/2/5, certification issue dates at 37/2/3, and additional titles at 50/45/0. Alias normalization and record boundaries can affect these comparisons; the mismatches remain errors in exact scoring. Additional-title comparison remains a set comparison rather than a full typed contribution-record association audit.

Column ordering and address continuation remain bounded heuristics. Destinations without a recoverable complete hostname, unsafe annotation destinations, annotations without a text anchor, arbitrary unlabelled multiline addresses and insufficient employment dates remain conservative omissions. Image-only hyperlink labels whose OCR text cannot be aligned are not claimed as supported. No external AI was enabled to fill gaps.
